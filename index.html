disclosure

Live audit of failures

A permanent record, not a scrolling ticker. Every entry is pulled from real commit history or an audit trail — dated, attributed, and left up after the fix. Click any row to expand.

What happened

Rule 3 — the confidence-ceiling check — could be undermined by FACT nodes that existed with confidence=None, which the integrity check didn't properly account for.

Why it happened

The rule assumed every FACT node would carry an explicit confidence value if it carried one at all; nodes without one weren't covered by the ceiling comparison.

How it was detected

Found in a live evaluation run, not a synthetic test.

What changed

Rule 3 now handles a missing confidence value correctly instead of letting it slip past the ceiling check. Fixed the same day it was found.

What happened

Trust Boundary's severity check used isinstance(f, dict) against Sentry's Match dataclass instances. The check was always False, so REJECT could never fire, regardless of how severe a finding was.

Why it happened

The check was written against an assumed data shape rather than Sentry's real return type.

How it was detected

Found while auditing Trust Boundary's integration against Sentry's real source, rather than trusting the interface as assumed.

What changed

The severity check was rewritten against the actual Match dataclass. REJECT fires correctly now. Fixed same day.

What happened

The Reasoning Kernel integration assumed a Kernel.evaluate() method that doesn't exist on the Kernel's real interface.

Why it happened

The integration was written against an assumed API surface rather than checked against the Reasoning Kernel's actual public interface before the two were wired together.

How it was detected

Surfaced during the same source-level audit that caught the REJECT-path bug above — checking real code instead of assumed docs.

What changed

Rewired against the real graph/transaction API. Fixed same day.

What happened

Rule 8, meant to catch circular reasoning, missed circular SUPPORTS chains — a reasoning graph containing a cycle could pass validation undetected.

Why it happened

The rule's cycle check didn't fully cover chains where a SUPPORTS edge closed a loop across multiple hops.

How it was detected

Found during rule-level testing of the integrity layer.

What changed

Rule 8 now detects circular SUPPORTS chains regardless of chain length; validation rejects them as it should. Fixed same day.

What happened

Warden's core matcher (word-Jaccard) was found to score inverted. On a 60-pair hand-labelled test set it produced an AUC of 0.332, below the 0.50 random baseline.

Why it happened

The matcher's scoring direction didn't line up with what a genuine match should indicate, so higher scores tracked mismatches more than matches.

How it was detected

Found during an adversarial review — hand-labelling a 60-pair test set and scoring the matcher against it. An AUC below random chance surfaced the inversion.

What changed

STATUS: ON HOLD — DETECTOR INVERTED. The matcher is being redesigned rather than patched; it stays flagged here, visible, until the redesign ships.

the operating principle

Rule zero

applies to every repository above, and to this page
Probabilistic systems should not adjudicate their own trust boundaries — deterministic rules should, and an AI agent's account of its own progress should be externally verified, never taken on faith. Every eval on this page reports its honest failures alongside its wins.
