Checks that don’t take an AI’s word for it.

An AI model's account of its own work is untrusted until something outside the model checks it. I build those checks: deterministic gates, containment tests and audit trails that decide whether an agent's action or claim holds up.

Since July 2026 I've directed coding agents to build them. I write the threat models, invariants and pass/fail tests, and the agents write most of the code. Every result on this page comes from tests and git history, including the ones that failed.

Armour

Tested
Action gate for AI agents

An agent proposes an action. Armour, not the agent, authorizes it, rejects it or escalates it to a human before anything runs. Unknown actions fail closed, and a model can't lower the risk rating of its own request. It's a policy boundary, not an operating-system sandbox.

174 unit tests pass, all 31 modeled mutants killed (in-repo tests)
Source

Chainmail

Tested
Authority across many agents

Extends Armour from one action to a whole fleet. Authority can only shrink as agents delegate it, never grow. Drift and re-entry signals rest on embedding similarity, which its docs call a heuristic, not proof.

243 tests

Sentry

Tested
Prompt-injection lint

A cheap, always-on check for injection and manipulation patterns, built from six deterministic rules. Runs as a command-line tool and in CI. Narrow on purpose.

22 of 22 tests pass, CI on 3 Python versions

Reasoning Kernel

Tested
Claim graph integrity

Eight rules over a graph of claims: provenance can't be faked, and a conclusion can't outrank what supports it. Evaluated on invented companies and people, so the model can't lean on what it already knows.

16 of 16 correct, 8 of 8 honest "not enough information" answers (24-case eval, not a field rate)

Mirror World and Mirror Shield

In progress
Local work, not yet published

Containment for frontier models. Each contained agent gets its own mirror world, so its writes never reach real data. A companion called Locket tracks what each agent seems to be after across turns and tightens as suspicion rises. Mirror Shield, a separate package the agent can't see or reach, learns from every recorded attempt. Even when a model games the mirror, its attempts still show which defenses to strengthen.

Found and fixed a timing side-channel, validated on held-out data

Security research

The same habit, pointed at real software: don't trust that code does what it says, go check.

How I look

I start where code changed most recently: areas that were just added, fixed or updated. New work is where bugs are most likely to hide.

When something looks wrong, I don't stop at the first symptom. I keep digging until I reach the root cause, and I use AI to move through unfamiliar codebases quickly.

What I publish

Counts and outcomes only. Several of these issues are acknowledged but not yet fixed, so case details stay private until the vendors resolve them.
