02 / core of the stack

Armour & Chainmail

The two systems the rest of the governance stack is built on: a single-action boundary, and the multi-agent layer extracted from it.

Armour

28 tests

A deterministic safety boundary for AI agents. No LLM, no autonomy loop, no self-modification.

Untrusted agent/model │ ActionProposal ▼ ArmourGate ├─ action allow-list ├─ effect/risk floor ├─ filesystem confinement ├─ public read-only network policy └─ dangerous-content rejection │ ├─ REJECTED ├─ ESCALATED ── human approval └─ AUTHORIZED │ ▼ hash-chained receipt
  • Unknown actions fail closed by default
  • Risk is the max of request, proposal, and verifier-inferred risk — a model can't lower it
  • Approvals bind to proposal ID, exact arguments, policy fingerprint, approving identity, expiry, and a single-use nonce
  • Includes an offline mutation-testing harness that challenges the gate with bounded adversarial variants, not just happy-path examples
Honest limitations — not an OS/container/process sandbox. Registered handlers remain trusted code. Approval replay protection is process-local; distributed deployments need a shared durable store. Cannot protect information already sent to a cloud model.

Chainmail

v5.1 · 101 tests

Policy-hard, context-fluid governance for long-running multi-agent systems. The links don't bend. The chain does.

Agent / harness Intent & planning │ chainmail.governor Trajectory objective continuity, authority, delegation, drift, cross-agent anomaly, replay, quorum │ execution_boundary Action │ OS / APIs Effect
  • Non-expanding delegation — authority can only shrink as it's passed between agents, never grow
  • Context can only tighten: drift, anomaly, and re-entry signals restrict or escalate, they never grant permission
  • Consensus across agents is treated as an anomaly signal, not a vote — agreement alone can't authorize an action
  • Re-entry is hard-gated: a reworded return to a previously refused objective escalates, but only when the agent's own lineage holds a real prior refusal
Honest limitations — a policy boundary, not a sandbox — the execution handler is the real containment. Contextual signals (drift, anomaly) are heuristics over embedding similarity, not proof. Live authority and replay state are single-process; a restart resets them. No formal proof of the non-authority-laundering property, only tests and mutation challenges.

Live audit of failures

A permanent record, not a scrolling ticker. Every entry is pulled from real commit history or an audit trail — dated, attributed, and left up after the fix.

AUG 9

Reasoning Kernel — confidence-ceiling bug

FIXED SAME DAY ▸

why it happened

The rule assumed every FACT node would carry an explicit confidence value if it carried one at all; nodes without one weren't covered by the ceiling comparison.

how it was detected

Found in a live evaluation run, not a synthetic test.

what changed

Rule 3 now handles a missing confidence value correctly instead of letting it slip past the ceiling check.

AUG 13

Trust Boundary — REJECT path never fired

FIXED SAME DAY ▸

why it happened

The check was written against an assumed data shape rather than Sentry's real return type.

how it was detected

Found while auditing Trust Boundary's integration against Sentry's real source, rather than trusting the interface as assumed.

what changed

The severity check was rewritten against the actual Match dataclass. REJECT fires correctly now.

AUG 13

Trust Boundary — integration assumed a method that didn't exist

FIXED SAME DAY ▸

why it happened

The integration was written against an assumed API surface rather than checked against the Reasoning Kernel's actual public interface before the two were wired together.

how it was detected

Surfaced during the same source-level audit that caught the REJECT-path bug above.

what changed

Rewired against the real graph/transaction API.

AUG 15

Reasoning Kernel — circular SUPPORTS chains undetected

FIXED SAME DAY ▸

why it happened

The rule's cycle check didn't fully cover chains where a SUPPORTS edge closed a loop across multiple hops.

how it was detected

Found during rule-level testing of the integrity layer.

what changed

Rule 8 now detects circular SUPPORTS chains regardless of chain length; validation rejects them as it should.

AUG 16

Warden — scoring inversion

ON HOLD ▸

why it happened

The matcher's scoring direction didn't line up with what a genuine match should indicate, so higher scores tracked mismatches more than matches.

how it was detected

Found during an adversarial review — hand-labelling a 60-pair test set and scoring the matcher against it. An AUC below random chance surfaced the inversion.

what changed

Status: on hold — detector inverted. The matcher is being redesigned rather than patched; it stays flagged here, visible, until the redesign ships.

04 / operating principle

Rule zero

Probabilistic systems should not adjudicate their own trust boundaries — deterministic rules should, and an AI agent's account of its own progress should be externally verified, never taken on faith. Every eval on this page reports its honest failures alongside its wins.

Most of the code across this portfolio was written by an AI agent, carrying Co-Authored-By: Claude in the commit history — visible to anyone who clicks through. My role was specifying the constraints, designing the evaluations, and catching what the agent got wrong. I see that as the more relevant skill for AI governance work than raw coding speed.
